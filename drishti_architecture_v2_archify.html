Architecture Matrix: Version 1.0 vs Version 2.0

Detailed technical breakdown of upgrades across computer vision, tracking, inference throttling, and cloud infrastructure.

Subsystem Version 1.0 (Baseline) Version 2.0 (New Architecture) Advantage / Performance Delta
OCR Architecture One-shot full snapshot using Google ML Kit Latin PP-OCRv4 DBNet Detector + SVTR/LCNet CTC Recognizer Universal multilingual support, genuine offline neural weights, zero cloud dependency.
Video Text Continuity Static capture only; user had to say "read this" repeatedly Continuous Real-Time Video Stream Reading Hands-free continuous reading mode while walking or examining groceries/medicine.
Text Region Tracking None (each snapshot was processed in total isolation) Lightweight Spatial-Temporal TextTracker (IoU + Centroid EMA) Filters video flicker, camera shake, and motion blur. Assigns persistent track IDs.
Recognition Throttling Full-frame recognition on all text regions on every call Selective Recognition Engine (Only Confirmed & Novel Regions) 85%–92% reduction in recognition passes; prevents mobile thermal throttling.
Frame Pipeline Concurrency Standard callback execution BoundedFrameDispatcher (Channel.CONFLATED Latest-Frame-Wins) Zero UI thread blocking; stale frames discarded automatically when inference is busy.
Reading Order & Speech Unsorted concatenated raw blocks Geometric Line Clustering + 15s Sliding Window Deduplication Natural top-to-bottom reading order; eliminates repetitive stuttering on same labels.
Safety Audio Priority Basic TTS flush Preemptive Safety Ducking Arbiter (Obstacle/Fall interrupts OCR immediately) Emergency hazard warnings always take precedence over OCR reading voice.
Visual Feedback / HUD Camera preview only OcrDebugOverlayView with Color-Coded Polygons & Track IDs Enables sighted caregivers, clinicians, and engineers to inspect OCR detections live.
Cloud Infrastructure Local token server scripts / adb reverse Vultr Cloud Compute (VPS) + Docker Compose + Caddy TLS 24/7 global cloud availability, automated HTTPS certificates, systemd resilience.

PP-OCRv4 Android Deployment & Inference Specification

Model signatures, mathematical formulations, operator constraints, and conversion instructions for mobile edge inference.

1. Model Signatures & Tensor Shapes

Stage A: PP-OCRv4 Detection (DBNet / LCNet_v2)

  • Input Shape: [1, 3, 320, 320] (Letterboxed with black border, preserving aspect ratio)
  • Normalization: mean = [0.485, 0.456, 0.406], std = [0.229, 0.224, 0.225], scale to [0.0, 1.0]
  • Output Shape: [1, 1, 320, 320] (Probability map tensor)
  • Post-processing: Binarize at τ = 0.3, extract contours, filter box score at τ = 0.6, Vatti polygon unclip with r = 1.6.

Stage B: PP-OCRv4 Recognition (SVTR / LCNet)

  • Input Shape: [1, 3, 48, 320] (Fixed height 48px, aspect ratio resized, width padded)
  • Dictionary: ppocr_keys_en.txt (66 alphanumeric + symbol tokens, index 0 reserved for CTC blank)
  • Output Shape: [1, 80, 67] (CTC logits over time steps and vocabulary)
  • Decoding: Greedy CTC argmax, collapse adjacent duplicates, remove blank token (index 0).

2. Model Acquisition & ONNX Export Command

# 1. Install conversion toolchains pip install paddlepaddle paddle2onnx onnxruntime # 2. Download official PP-OCRv4 inference tarballs wget https://paddleocr.bj.bcebos.com/PP-OCRv4/chinese/ch_PP-OCRv4_det_infer.tar wget https://paddleocr.bj.bcebos.com/PP-OCRv4/english/en_PP-OCRv4_rec_infer.tar tar -xf ch_PP-OCRv4_det_infer.tar tar -xf en_PP-OCRv4_rec_infer.tar # 3. Convert DBNet Detector to ONNX with opset 14 paddle2onnx --model_dir ./ch_PP-OCRv4_det_infer \ --model_filename inference.pdmodel \ --params_filename inference.pdiparams \ --save_file ch_PP-OCRv4_det_infer.onnx \ --opset_version 14 # 4. Convert SVTR Recognizer to ONNX with opset 14 paddle2onnx --model_dir ./en_PP-OCRv4_rec_infer \ --model_filename inference.pdmodel \ --params_filename inference.pdiparams \ --save_file en_PP-OCRv4_rec_infer.onnx \ --opset_version 14
